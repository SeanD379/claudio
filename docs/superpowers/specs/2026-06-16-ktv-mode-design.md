> 日期：2026-06-16
> 最后更新：2026-06-21

## 一、概述

KTV 模式是 Claudio 的第二模式，核心理念是**沉浸式音综舞台体验**。不是传统 KTV 的"对着字幕唱"，而是让用户成为舞台上的那个人——当歌曲播放时，殿堂级的灯光舞美配合演唱，让用户真实体验在音综舞台上的演出感。

参考对象：湖南卫视《歌手2024》《歌手2025》《歌手2026》的舞台舞美设计。

## 三、开场过渡（6 秒）— 渐进爆发式

> **2026-06-21 重做：** 从单调线性流程改为渐进爆发式演唱会开场，Canvas 全绘制

从听歌模式切换到 KTV 模式时的沉浸式开场：

| 时间 | 阶段 | 视觉效果 |
|------|------|----------|
| 0.0-0.8s | 黑暗序幕 | 全黑，微弱桁架轮廓线浮现（0.06 透明度白线） |
| 0.8-1.8s | 第一道光 | 一道暖白光束从左扫到右，地面留一道微弱光痕 |
| 1.5-2.2s | 心跳节奏 | LED 条双闪心跳节奏（快亮-暗-慢亮），低频脉冲感 |
| 2.2-3.2s | 三束齐开 | 三道光束同时亮起（暖白/冰蓝/粉），从中间向两边展开 |
| 3.0-4.0s | 大屏点亮 | LED 大屏逐块点亮（左→右→中→地屏），带颜色渐变 |
| 3.5-5.0s | 粒子飘落 | Canvas 绘制金色/白色光点缓缓飘落 |
| 4.0-4.5s | 汇聚爆发 | 所有光束收拢中心→白光爆闪→粒子爆炸式扩散 |
| 4.5-5.5s | 全景展开 | 灯光向外展开，全舞台呈现 |
| 5.5-6.0s | 淡出过渡 | 整体淡出，进入 KTV 舞台 |

**技术实现：**
- 全屏 Canvas 绘制（光束为三角形渐变光锥，粒子为带光晕的圆点）
- `requestAnimationFrame` 驱动，与 KtvStage 渲染模式一致
- 光束使用 `globalCompositeOperation = 'lighter'` 加法混合
- 粒子系统支持持续生成 + 爆发生成两种模式
- 桁架轮廓线在开场全程微弱可见，提供空间感

**跳过机制**：点击屏幕可跳过开场，直接进入舞台

## 四、舞台构成（Canvas 纯绘制）

> **2026-06-20 更新：** 舞台改为全 Canvas 绘制，不再使用 AI 生成的底图。

舞台全部由 `<canvas>` 实时渲染，按 16:9 虚拟坐标系绘制，居中显示在任意屏幕上。

```
  ══════════════ 灯架横梁（5 个节点）══════════════
  ╱    ╲    ╱    ╲    ╱    ╲    ╱    ╲    ╱    ╲     ← 12 束光束灯
                                                    从横梁 12 个点发出
 ┌──────┐ ┌──────────────────┐ ┌──────┐
 │      │ │                  │ │      │
 │ 副屏 │ │    LED 中央大屏    │ │ 副屏 │
 │  左  │ │    （歌词区域）    │ │  右  │
 │ 频谱 │ │                  │ │ 频谱 │
 │ 可视 │ │  金色边框 + 呼吸光晕 │ │ 可视 │
 │ 化   │ │                  │ │ 化   │
 └──────┘ └──────────────────┘ └──────┘

 ═══════════════════════════════════════════════
                   舞台地面
           （深色 + 反射光带 + 倒影）
```

### Canvas 绘制层级（从底到顶）

| 层 | 绘制内容 | 说明 |

| 1 | 背景氛围 | 径向渐变环境光 |
| 2 | 舞台地面 | 深色底 + 反射光带 + 地砖网格 + 接缝线 |
| 3 | LED 墙（三屏） | 中央大屏 44%×44% + 左右副屏 13%×38% |
| 4 | 桁架 | 弧形横梁 + 侧立柱 + 发光铆钉 |
| 5 | 30 盏灯光 | 10 种类型统一引擎渲染（详见灯光设备清单） |
| 6 | Beat 闪光 | 节拍脉冲光晕 |
| 7 | 粒子 | 漂浮光点 |
| 8 | 烟雾大气层 | 径向渐变模拟散射 |
| 9 | 暗角 | 椭圆形渐暗 |

### 视觉元素
- **LED 中央大屏** — 44% 宽 × 44% 高，暗色底板 + 呼吸光晕 + 边框，歌词显示区域
- **LED 左右副屏** — 13% 宽 × 38% 高，统一律动波形可视化（18 根柱状条，独立随机跳动 + 频段微弱调制 + beat 联动）
- **桁架** — 弧形金属横梁 + 两侧立柱 + 交叉支撑 + 发光铆钉
- **舞台地面** — 深色底 + 反射光带 + 地砖网格 + 接缝线发光
- **粒子系统** — 漂浮光点，随能量变化密度和亮度
- **暗角** — 椭圆形渐暗，引导视线到中央

### 灯光设备清单（30 盏灯，10 种类型）

> **2026-06-20 新增**

| 类型 | 数量 | 位置 | 作用 | 运动方式 |
|------|------|------|------|----------|
| 帕灯/染色灯 | 4 盏 | 桁架两侧（0.15,0.38,0.62,0.85） | 宽角度地面染色 | 脉冲呼吸 |
| 光束灯 | 6 盏 | 桁架均匀分布 | 空中切割光束矩阵 | 缓慢扫动 |
| 切割灯 | 3 盏 | 桁架偏上（0.22,0.50,0.78） | 精准光斑控制 | 慢速扫动 |
| 成像灯 | 2 盏 | 桁架两侧（0.10,0.90） | 交叉投射 | 呼吸脉冲 |
| 三合一电脑灯 | 3 盏 | 桁架中心区（0.30,0.50,0.70） | 强光束+染色 | 扫动 |
| 聚光灯 | 2 盏 | 顶部中央（0.35,0.65） | 主舞台聚焦 | 极慢扫动 |
| 面光灯 | 4 盏 | 桁架前端（0.18,0.38,0.62,0.82） | 前方补光 | 静态 |
| 观众灯 | 2 盏 | 桁架远端（0.08,0.92） | 扫射观众区（y=0.95） | 缓慢扫动 |
| 追光灯 | 2 盏 | 画布外左右（-0.05,1.05） | 窄长跟踪光柱 | XY双向扫动 |

**灯光渲染引擎：** 统一的 `drawAllLights` 函数，数据驱动，每盏灯独立配置：
- 7 层高斯切片体积光（multi-slice trapezoid + Gaussian falloff）
- 外层柔光锥 + 落地光斑 + 灯头发光点
- 所有灯光层使用 `globalCompositeOperation = 'lighter'`（加法混合）
- 运动速度已调慢（0.12~0.4 rad/s），模拟真实演唱会缓慢摆动

### 16:9 虚拟视口
- Canvas 按实际屏幕尺寸绘制，但内部使用 16:9 虚拟坐标系
- 不足部分填充纯黑（letterbox/pillarbox）
- 所有舞台元素基于虚拟坐标定位，保证任何屏幕比例下舞台不变形

## 五、动态灯光系统

### 三层驱动架构

#### 1. 段落驱动（基调层）
- **Verse** → 柔和，低饱和，少量暖光，呼吸节奏
- **Pre-chorus** → 亮度渐升，光束开始聚拢
- **Chorus** → 全场爆发，光束矩阵扫射，色彩饱和度拉满
- **Bridge** → 留白，只剩一束追光
- **Outro** → 灯光逐层熄灭，回到黑暗

#### 2. 节拍驱动（律动层）
- 每一拍，光束有微弱脉冲（亮度 ±10%）
- 重音时，地屏有涟漪扩散
- 副歌段落，光束跟着 BPM 做扇形扫射

#### 3. 情绪自适应（风格层）— 6 种舞美风格

> **2026-06-20 更新：** 从高饱和霓虹色改为柔和专业舞台色系

| 风格 | 对应 Mood | 主色 | 辅色 | 强调色 |
|------|-----------|------|------|--------|
| 月光 | minimal | 蓝灰(140,160,210) | 深蓝灰(100,120,170) | 浅蓝(190,200,230) |
| 暖阳 | warm | 金黄(230,175,100) | 暖橙(200,140,70) | 暖白(245,210,160) |
| 玫瑰 | cyber | 柔粉(200,110,155) | 深粉(170,90,130) | 浅粉(225,170,200) |
| 冰蓝 | tech | 清蓝(80,150,210) | 深蓝(60,120,180) | 浅蓝(150,200,240) |
| 琥珀 | redGold | 暖琥珀(210,145,70) | 深琥珀(180,110,50) | 浅琥珀(235,195,130) |
| 紫晶 | rainbow | 柔紫(150,110,190) | 深紫(120,85,160) | 浅紫(190,160,220) |

**颜色过渡：** mood 切换时，所有颜色（primary/secondary/accent）在 2 秒内 lerp 渐变，避免跳切。

### 音频分析方案
- **主判断：** Web Audio API 实时分析（`useAudioAnalyzer` hook）
  - FFT_SIZE = 256，SMOOTHING = 0.8
  - 输出：energy、bass、mid、high、beat、mood、frequency（Uint8Array）、freqBoosted（放大后频谱）
  - freqBoosted：每个 bin 取 ±2 邻居峰值 × 2.5 倍增益，用于副屏可视化
- **辅助修正：** 歌词情感分析（有歌词时微调色温，纯音乐时仅依赖音频分析）

## 六、镜头微动

固定视角基础上加入极慢的镜头微动，消除长时间观看的视觉疲劳：

- **Verse** → 镜头微微前推（1-2% 缩放），营造亲近感
- **Chorus** → 镜头微微后拉，展示更完整的舞台
- **歌曲间** → 镜头做缓慢的全景扫视（像导播切机位）

幅度极小，用户不会明显察觉，但画面一直在"呼吸"。

---

## 七、歌曲转场编排

连续播放时，歌与歌之间的过渡处理：

1. 当前歌曲结束 → 灯光收束（2 秒渐暗）
2. 黑暗中舞台重置（1 秒）
3. 下一首歌前奏响起 → 灯光根据新歌情绪重新亮起

每首歌都像一个独立的舞台时刻，而非连续背景音乐。

---

## 八、氛围粒子系统

舞台上方的粒子效果，随音乐变化：

- **抒情慢歌** → 光点像雪花/萤火虫缓慢飘落
- **激情快歌** → 光点像火星/能量粒子向上飞散
- **副歌高潮** → 粒子密度爆发，像烟花绽放
- **间奏留白** → 粒子消散，只剩干净光束

轻量粒子系统叠加在 WebGL 场景上，几十个粒子即可，性能可控。

### 9.3 队列联动机制

**状态管理：** `useKtvQueue` zustand store
- `queue: Song[]` — 待唱队列
- `addSong(song)` — 加入队列末尾
- `removeSong(index)` — 从队列移除
- `clearQueue()` — 清空队列
- `playNext()` — 出队第一首并返回

**播放联动：**
- 进入 KTV 模式时，`usePlayer.nextSong` 被覆盖为队列优先版本
- 点"下一首"时：有队列歌曲 → 从队列取；无队列 → 走原播放列表
- 歌曲自然播放结束（`onPlaylistEnd`）：同样从队列取下一首
- 退出 KTV 模式时，恢复原始 `nextSong` 行为

## 十三、架构隔离原则

KTV 模式与默认听歌模式的隔离保证：

- KTV 模式是**独立的状态分支**，进入/退出做完整状态切换
- 默认模式的所有组件在 KTV 模式下只是**被隐藏**，不是被销毁
- 退出 KTV 模式时，所有默认组件**原样恢复**，歌曲继续播放不中断
- 两个模式共享底层播放引擎（usePlayer），但 UI 层完全隔离
- **新增功能不影响默认模式的任何现有行为**

## 十四、舞台效果方案（Canvas 动态渲染）

> **2026-06-20 更新：** 所有舞台效果由 Canvas 根据 mood 实时渲染；灯光系统完全重写为 30 盏灯数据驱动；舞美风格改为柔和专业色系

6 种舞美风格对应 6 种柔和色彩方案（详见第五节表格）。

### 实现方式
- **底图：** 无，全部 Canvas 绘制
- **灯光：** 30 盏灯统一引擎渲染，10 种类型，数据驱动
- **颜色过渡：** mood 切换时 2 秒 lerp 渐变
- **副屏可视化：** 18 根柱状条，每根柱子有独立的随机频率组合（3 个 sin 波叠加），高低不一独立跳动，频段数据做微弱调制（0.8~1.3 范围），beat 联动保留，暂停时静止
- **加法混合：** 所有灯光层使用 `lighter` 混合模式，实现真实灯光叠加效果
- **体积光：** 7 层高斯切片梯形渲染，模拟光束在空气中的散射
