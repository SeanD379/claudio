# 音乐日历「历史上的今天」联网生成设计

## 状态

已由用户确认，日期为 2026-08-30。

## 目标

- 历史内容跟随音乐日历中选中的日期，而不是只跟随现实中的今天。
- 首次访问某个“展示年份 + 月日”时联网获取音乐相关历史事件，并按现有时间线格式生成最多 3 条内容。
- 生成成功后保存到 MySQL；同一展示年份再次打开时直接返回存档，内容不随刷新改变。
- 同一个月日在不同展示年份使用不同事件，已经展示过的事件永不重复。
- 联网失败时使用现有 `src/data/music-history.json` 作为候选来源，并继续执行相同的去重规则。

## 非目标

- 不加入后台定时任务；内容在用户首次打开日期时按需生成。
- 不调用付费 AI 模型，不新增模型费用或模型 API 依赖。
- 不修改播放记录、月历统计和登录逻辑。
- 不保证每个日期永远都有 3 条新事件；候选耗尽时明确显示暂无新内容，不重复旧事件。

## 数据来源

主来源使用中文维基百科的 MediaWiki Action API。请求日期页面（例如 `8月30日`）的当前页面内容，再从“大事记、出生、逝世”等条目中筛选音乐事件。选择 Action API 而不是 Wikifeeds API，因为 Wikimedia 已公告 Wikifeeds 从 2026 年 7 月开始逐步弃用。

候选事件必须包含至少一个音乐语义关键词，例如音乐、歌曲、歌手、乐队、作曲、演奏、专辑、唱片、发行、演唱会、音乐节、格莱美、摇滚、爵士、古典、说唱、DJ、制作人等。筛选只用于候选选择；保存前会清理维基标记、引用标记和多余空白。

如果联网请求失败、页面不存在或筛选后没有可用候选，则读取现有本地音乐历史数据作为备用候选。返回内容需要标记来源类型，便于后续排查。

## 数据模型

新增 `MusicHistoryEntry`：

- `id`: 主键。
- `monthDay`: `MM-DD`，用于归类相同月日。
- `displayYear`: 用户在日历中选择的年份，决定该年显示哪一组内容。
- `slot`: 该批次中的顺序，范围 0-2。
- `eventYear`: 历史事件实际发生年份。
- `event`: 清理后的中文事件描述。
- `artist`: 可选音乐人或团体名称；无法可靠提取时为 null。
- `sourceType`: `wikimedia` 或 `local`。
- `sourceTitle`: 来源页面标题。
- `sourceUrl`: 可选来源链接。
- `fingerprint`: 对 `monthDay + eventYear + 规范化事件文本` 计算的 SHA-256。
- `createdAt`: 存档时间。

约束：

- `(monthDay, displayYear, slot)` 唯一，保证同一展示批次稳定。
- `(monthDay, fingerprint)` 唯一，保证同一个月日跨展示年份不重复事件。
- 数据库写入使用事务；并发首次请求产生唯一键冲突时重新读取已保存批次。

## API 设计

保留现有 `GET /api/calendar/history`，参数改为：

```text
year=2026&month=08&day=30
```

处理顺序：

1. 验证年份和真实日历日期。
2. 查询 `monthDay + displayYear` 的已存档事件；存在则直接返回。
3. 通过 MediaWiki Action API 获取对应中文日期页面。
4. 解析候选、过滤音乐语义、清理格式并计算指纹。
5. 查询该 `monthDay` 的所有历史指纹，排除已使用事件。
6. 按事件年份与稳定指纹排序后选取最多 3 条，确保同一输入可复现。
7. 若联网候选为空，合并本地备用候选后再次去重。
8. 在事务中保存并返回。

响应格式：

```json
{
  "events": [
    {
      "year": 1969,
      "event": "示例音乐历史事件",
      "artist": null,
      "sourceUrl": "https://zh.wikipedia.org/wiki/8月30日"
    }
  ],
  "source": "wikimedia",
  "saved": true,
  "exhausted": false
}
```

如果没有未使用候选，返回空数组和 `exhausted: true`，HTTP 状态仍为 200。

## 前端数据流

`useCalendar` 在选中日期变化时把完整年份、月份和日期传给历史 API。历史内容继续通过 `DayDetail` 传入 `HistoryToday`，保留当前日期时间线格式。

增加独立的历史加载和错误状态：

- 加载中：在历史卡片显示“正在整理这一天的音乐记忆…”。
- 已生成：展示最多 3 条时间线，并保留来源链接。
- 候选耗尽：显示“暂时没有新的音乐历史事件”。
- 请求失败且本地备用也不可用：显示“历史内容暂时无法获取”，不影响播放统计区域。

## 错误处理与运行环境

- 外部请求设置超时，并发送明确的 `User-Agent`，遵守 Wikimedia 访问政策。
- API 返回结构异常时视为外部请求失败，进入本地备用路径。
- 数据库错误返回 500；客户端显示独立错误状态，不隐藏“我的今天”。
- 本地开发需要让 Next.js 服务拥有外网访问权限；生产环境由 Netlify Server Function 发起请求。
- 不把外部响应原样写入数据库，避免保存 HTML、脚本或不可控标记。

## 验证标准

- 首次请求某日期会生成并保存不超过 3 条音乐事件。
- 相同日期和展示年份重复请求返回完全相同的数据库记录。
- 相同月日在不同展示年份不会返回相同指纹。
- 网络失败时会使用本地数据且仍不重复。
- 候选耗尽时不会复用旧事件。
- 未登录用户仍可查看公开历史事件。
- 月度播放统计和当天播放详情行为保持不变。
- TypeScript、Prisma 校验和相关接口手动测试通过。
